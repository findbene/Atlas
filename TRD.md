## 1. Purpose and Scope

This document specifies the concrete technical implementation of Atlas: the stack versions, API surface, data model, validation contract, environment variable matrix, and non-functional requirements. It is written for engineers building or integrating with the platform.

**In scope:** Stack versions, package names and versions, route inventory, Drizzle schema (tables and enums), grading function signatures, auth middleware contracts, env var names and roles, performance budgets, quality gates.

**Out of scope:** Architectural rationale (see ARD.md), product feature descriptions (see PRD.md), UI/UX and visual design (see DRD.md).

| `test` | api-server | `vitest run --exclude '**/*.integration.test.ts'` | Unit tests (excludes DB integration). |
| `test:integration` | api-server | `INTEGRATION_TEST_DB_ALLOW=1 vitest run` | DB integration tests. |
| `test` | atlas | `vitest run` | Frontend unit tests. |
| `codegen` | api-spec | `orval` | Regenerates `api-client-react` and `api-zod` from `openapi.yaml`. |

### 3.3 Codegen Pipeline

Orval reads `lib/api-spec/openapi.yaml` and emits two outputs:

| Output package | Client mode | Target path |
|---|---|---|
| `@workspace/api-client-react` | `react-query` (split) | `lib/api-client-react/src/generated/` |
| `@workspace/api-zod` | `zod` (split) | `lib/api-zod/src/generated/` |

Base URL: `/api`. Custom fetch mutator: `lib/api-client-react/src/custom-fetch.ts`. Coercion enabled for query/param/body booleans, numbers, and strings.

Routes not covered by the OpenAPI spec (SSE streaming, plain-fetch endpoints) use `fetch` directly in the frontend.

### 5.3 Migration Strategy

Migrations are managed by Drizzle Kit (verify `drizzle-kit` is present in devDependencies). Conventions observed in the codebase:

- New columns default to `NOT NULL` with safe defaults where possible; nullable when pre-existing rows must remain valid without a backfill.
- Phase-tagged comments document the introducing phase of each column (`-- Phase N`).
- Backfill scripts (`scripts/`) handle data migration after additive schema changes.
- No destructive migrations have been confirmed; archived data is soft-deleted or flagged, not removed.

## 6. Validation and Grading Technical Contract

### 6.1 The Nine Validation Kinds

| Kind | Config shape | Semantics | Server-graded? |
|---|---|---|---|
| `self_attest` | (none) | Always passes. Learner self-declares. | Yes (trivial pass) |
| `exact` | (none — uses `step.expectedOutput`) | Trimmed string equality against `expectedOutput`. | Yes |
| `contains` | `{ needle? }` (legacy) or `{ needles[], match?, caseInsensitive? }` (Phase 56) | Literal substring match. See §6.3 for full semantics matrix. | Yes |
| `regex` | `{ pattern: string, flags?: string }` | `RegExp(pattern, flags).test(submission)`. Invalid regex fails closed with feedback. | Yes |
| `numeric_tolerance` | (verify shape) | Numeric value within tolerance band. | Yes (verify full implementation) |
| `csv_set_equal` | `{ spec: CsvSetEqualSpec }` | Row-set comparison. Opt-in via `spec.serverGrade === true` (Phase 57A). Without flag: BC auto-pass. | Opt-in (Phase 57A) |
| `csv_ordered` | (verify shape) | Ordered CSV comparison. | Yes (verify full implementation) |
| `json_equal` | (verify shape) | JSON structure equality. | Yes (verify full implementation) |
| `sql_resultset` | (verify shape) | SQL result set comparison. | Yes (verify full implementation) |

### 6.2 gradeSubmission Signature

File: `artifacts/api-server/src/lib/grading.ts`

```typescript
export type GradableStep = {
  validationType: string | null;
  validationConfig: unknown;
  expectedOutput: string | null;
};

export type GradingOutcome = {
  passed: boolean;
  feedback: string;
};

export function gradeSubmission(
  step: GradableStep,
  submission: string | null | undefined,
): GradingOutcome
```

**Contract invariants:**
- Pure function. No DB writes, no XP accounting, no side effects of any kind.
- This function is the single source of truth for both `/check` and `/submit`. Changes here affect both endpoints simultaneously.
- Unknown or null `validationType` falls through to `{ passed: true, feedback: "Step completed." }` (legacy BC behavior).
- Malformed configs for structured kinds (`contains`, `csv_set_equal`) fail **closed**: `{ passed: false, feedback: "Grading config is malformed…" }`. They never produce a silent pass.

### 6.3 contains Semantics Matrix (Phase 56)

| Config shape | Path | Behavior |
|---|---|---|
| `{}` | LEGACY-FALLBACK | `needle = expectedOutput ?? ""`; `submission.includes(needle)` |
| `{ needle }` | LEGACY | `submission.includes(needle)` |
| `{ needle, caseInsensitive: true }` | LEGACY-CI | Lowercase both, then includes |
| `{ needles[] }` | MULTI-ALL | Every needle must be found |
| `{ needles[], match: "all" }` | MULTI-ALL | Every needle must be found |
| `{ needles[], match: "any" }` | MULTI-ANY | At least one needle found |
| `{ needles[], caseInsensitive: true }` | MULTI-CI | Combinator on lowercased strings |
| `{ needle, needles[] }` | MULTI-* | `needles` wins; `needle` ignored |
| `{ needle, match: "any" }` (no needles) | LEGACY | `match` silently ignored; single-needle path |
| `{ caseInsensitive: "yes" }` | COERCE-FALSE | Non-boolean `caseInsensitive` coerced to false |
| `{ needles: [] }` | MALFORMED | Fails closed |
| `{ needles: non-array \| non-string item }` | MALFORMED | Fails closed |
| `{ needles[], match: "weird" }` | MALFORMED | Fails closed |

Hard limit: `MAX_NEEDLES = 16`.

### 6.4 /check vs /submit Semantics

| Behavior | `/check` | `/submit` |
|---|---|---|
| Calls `gradeSubmission` | Yes | Yes |
| Writes to `user_step_completions` | No | Yes |
| Awards XP | No | Yes (on pass) |
| Bumps streak | No | Yes (on pass) |
| Sends completion email | No | Yes (on project completion) |
| Updates `user_progress` | No | Yes |
| Records `submission_excerpt` / `submission_sha256` | No | Yes (on pass; write-once) |

### 6.5 Dark-Ship and BC-Audit Requirement

New graders must follow the dark-ship pattern:

1. Introduce the grader behind an explicit opt-in flag in `validationConfig` (e.g., `serverGrade: true`).
2. Without the flag, return the pre-existing BC auto-pass tuple byte-for-byte.
3. Gate shipping on a BC audit: `audit:csv-set-equal-bc` (and the equivalent for each new grader) must pass before merging changes to visible steps.
4. Run `audit:contains-bc` when the `contains` grader or any `contains`-typed step seed changes.

### 6.6 Signed Run Envelope

**Route:** `POST /api/runs/sign` (Phase 46)

**Purpose:** Mint a server-signed `SignedRunEnvelope` binding a `RunCapture` (client-captured Pyodide/DuckDB result) to `(userId, projectId, stepId, validationKind)`. The signature proves Atlas issued the envelope; it does not prove the learner executed the code.

**Signable kinds only:** `json_equal`, `numeric_tolerance`, `sql_resultset`, `csv_set_equal`, `csv_ordered`. All others return 422.

**Payload caps before signing:**

| Field | Cap |
|---|---|
| `code` | 32,000 bytes (UTF-8) |
| `stdout` | 64,000 bytes |
| `stderr` | 64,000 bytes |
| `columns` | 256 columns |
| `rows` | 5,000 rows |

**TTL:** 10 minutes from signing.

**Secret:** `RUN_ENVELOPE_SIGNING_SECRET`. Missing secret → 503 (graceful degradation). Hard-fail at boot in production (`src/index.ts`).

**Nonce table:** `run_envelope_nonces`. INSERT-only at verify time (Phase 47+). Nightly janitor cleans expired rows.

## 7. Authentication and Authorization

### 7.1 Clerk Integration

Atlas uses Clerk as the identity provider. The backend uses `@clerk/express ^2.1.9`.

**Flow:**
1. Frontend authenticates via `@clerk/react` and receives a session JWT.
2. JWT is attached to every API request (Authorization header or cookie — verify transport mechanism in `custom-fetch.ts`).
3. `getAuth(req)` from `@clerk/express` extracts `userId` (Clerk user ID) from the token.
4. `requireAuth` middleware calls `loadOrProvisionUser(clerkId)`: looks up the local `users` row by `clerk_id`, or creates one by calling Clerk's user API and inserting into the DB.

**In-process user cache:** `Map<clerkId, LocalUser>`. Per-process, cleared on restart. After any write that mutates a cached column, call `invalidateUserCache(clerkId)` or the stale value persists until restart.

**User provisioning edge cases:**
- If Clerk API is unavailable during provisioning, a placeholder email (`{clerkId}@users.atlasprojects.dev`) is used.
- On email-uniqueness collision at insert, the same placeholder email is retried.

### 7.2 Middleware Reference

| Middleware | Behavior on failure | Usage |
|---|---|---|
| `requireAuth` | 401 JSON `{ error: "Unauthorized" }` | All authenticated routes |
| `requireAdmin` | 401 (if unauthenticated) or 403 (if authenticated but not admin) | Admin-only routes (`role = 'admin'`) |

**404-not-403 policy:** Routes that gate on enrollment, premium subscription, or project visibility return 404 for hidden/inaccessible resources rather than 403. This prevents existence leaks. See `runs-sign.ts` for the canonical implementation.

### 7.3 Authorization Gates (layered)

For `POST /api/runs/sign`, the gate chain is:
1. `requireAuth` — valid Clerk session.
2. Step belongs to the specified project (cross-project FK forge defense).
3. `project.learnerVisible === true` — archived projects look like 404.
4. Premium gate: `project.isPremium && user.subscriptionTier !== 'pro'` → 403.
5. Enrollment: `user_progress` row must exist for `(user, project)`.
6. Validation kind is in `SIGNABLE_KINDS`.

Other routes follow analogous layering; the pattern is consistent across the codebase.

## 12. Technical Constraints and Assumptions

| Constraint | Detail |
|---|---|
| Pyodide cannot be cancelled mid-run | Once a Python execution is dispatched to the Pyodide WASM runtime in the browser, there is no cancellation API. The UI must communicate this to learners (e.g., disable the Run button during execution). Long-running cells will block the browser main thread until completion or timeout. |
| DuckDB-WASM is browser-only | DuckDB-WASM runs exclusively in the browser. Server-side SQL validation for `sql_resultset` steps uses a different mechanism (verify implementation in `execution-core`). |
| Per-process Clerk user cache | The in-memory `userCache` Map in `auth.ts` is per-process. In a multi-instance deployment, two concurrent requests for the same user on different instances will each hit the DB. The cache provides single-process optimization only; it is not a distributed cache. After any DB write that mutates cached columns, `invalidateUserCache` must be called within the same process to maintain consistency. |
| Neon single vs multi-instance | Neon PostgreSQL serverless has cold-start latency on the first connection after a period of inactivity. Connection pooling settings must account for this. Multi-instance deployments of the API server share the same Neon DB; advisory locks (verify usage) handle concurrent write contention. |
| `stripe-replit-sync` dependency | The `stripe-replit-sync` package and the `stripe.*` Postgres schema are Replit-specific infrastructure. The migration to direct Stripe webhook handling is in progress. Until complete, pricing lookups fall back to env vars when the synced schema is unavailable. |
| Pyodide version discrepancy | `package.json` declares `pyodide ^0.29.3`; FACT PACK states 0.28.4 as the CDN-loaded version. Confirm which version is actually loaded at runtime and align the declaration. |
| No PWA in production | `vite-plugin-pwa` is present in devDependencies but no service worker or web manifest has been confirmed as deployed. Do not rely on offline capabilities until this is explicitly implemented and tested. |
| OpenAPI coverage | The Orval-generated client (`@workspace/api-client-react`) does not cover all routes. SSE endpoints (`/api/ai/chat`), routes added after the last OpenAPI sync, and routes under active development use plain `fetch`. Keep `openapi.yaml` in sync with the route inventory when adding new endpoints. |
| TypeScript strict — no `any` | `tsconfig` enforces strict mode. `any` is prohibited. Use proper types or `unknown` with type guards at untrusted boundaries. |
