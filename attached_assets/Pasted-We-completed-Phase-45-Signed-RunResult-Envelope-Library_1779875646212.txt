PHASE 46 — Run Signing API + Nonce Store, No Submit Integration

Goal:
Create the backend signing endpoint and replay-protection storage needed for signed RunResult validation, without changing /submit completion semantics yet.

This phase should expose a controlled POST /api/runs/sign endpoint that signs runtime captures using the Phase 45 envelope library.

Do not wire signed envelopes into /submit in this phase.
Do not reclassify json_equal as enforced in this phase.

Expected implementation:

A. Database / nonce storage
Add the minimum table needed for replay protection, if required by the Phase 44 design.

Suggested table concept:
run_result_nonces or run_envelopes

Fields may include:

* id
* nonce
* userId
* projectId
* stepId
* submissionSha256
* outputSha256
* issuedAt
* expiresAt
* usedAt or consumedAt if relevant
* createdAt

Rules:

* nonce must be unique.
* rows should expire.
* no raw learner code should be stored.
* no raw stdout/stderr should be stored unless absolutely necessary.
* prefer hashes and metadata only.

B. POST /api/runs/sign
Authenticated endpoint.

Input:

* RunCapture-like payload:

  * projectId or projectSlug
  * stepId
  * code
  * stdout
  * stderr
  * exitCode
  * validationKind
  * nonce or server-generated nonce depending on design

Behavior:

* authenticate user
* verify user is enrolled in / allowed to access project
* verify step belongs to project
* verify validation kind is in allow-list
* compute submission/output hashes server-side
* generate or validate nonce
* sign envelope using Phase 45 library
* persist nonce metadata for replay protection
* return signed envelope

C. Signing secret
Use an environment variable such as RUN_ENVELOPE_HMAC_SECRET.

Rules:

* fail closed if missing in non-test runtime.
* tests may inject deterministic secret.
* do not log secret.
* do not commit secret.

D. Janitor / expiry

Prefer a small cleanup script if easy.
