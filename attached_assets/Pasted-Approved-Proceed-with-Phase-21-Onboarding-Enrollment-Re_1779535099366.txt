T002 — API endpoints
Implement minimal authenticated API endpoints.

Endpoint 1:
POST /api/enrollments

Body:
{ projectSlug: string }

Behavior:

* requireAuth
* projectSlug must resolve to learner_visible=true project
* hidden/archive slugs return 404, not 403
* creates or reuses user_progress for (userId, projectId)
* idempotent: repeated enrollment does not create duplicates
* sets or returns currentStepId as the first step if no progress exists
* returns projectId, projectSlug, currentStepId, currentStepNumber if available

Endpoint 2:
GET /api/dashboard

Behavior:

* requireAuth
* returns inProgress projects
* returns completed projects if already supported
* returns a Resume card payload:

  * project title
  * project slug
  * course
  * current step
  * total steps
  * deep link target
* excludes hidden/archive projects
* never exposes internal anchor metadata

Endpoint 3:
GET /api/onboarding/state

Behavior:

* requireAuth
* returns whether onboarding is complete
* returns enough state for frontend onboarding stepper

Endpoint 4:
POST /api/onboarding/complete

Behavior:

* requireAuth
* idempotently marks onboarding complete
* if using onboarding_completed_at, sets it once or updates safely depending on existing conventions
