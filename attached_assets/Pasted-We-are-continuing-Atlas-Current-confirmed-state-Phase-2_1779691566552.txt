## 4. Check vs Submit architecture

Formally separate two actions.

### Run Check / Evaluate Step

This is:
- low-stakes
- repeatable
- step-scoped
- used during learning
- allowed many times
- not final completion
- not final confetti

It should:
- capture the learner’s current code/query/config/output
- run relevant checks
- return structured feedback
- save step validation state
- unlock the next step only when criteria pass

### Submit Final Project

This is:
- high-stakes
- project-scoped
- intentional
- completion-oriented
- evidence-producing

It should:
- validate all required steps/checks
- create a final validation run
- snapshot completion evidence
- record project completion only if criteria pass
- trigger earned reward only once
- return remediation if incomplete
