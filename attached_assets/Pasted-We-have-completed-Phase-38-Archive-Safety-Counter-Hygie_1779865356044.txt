PHASE 39 — Durable Enrollment Counter Writer + Backfill

Goal:
Make projects.enrolled_count accurate and durable so display/API surfaces no longer pass stale zeroes to clients.

Why:
Phase 38 correctly stopped using enrolled_count for archive safety, but the counter still has no writer. It remains stale for display/API/social-proof surfaces. We should fix that now while the counter issue is fresh.

Start with a read-only audit.

Read first:
1. HANDOFF.md
2. replit.md
3. docs/phases/INDEX.md
4. docs/phases/phase-38-archive-safety-counter-hygiene.md
5. scripts/src/lib/enrollment-check.ts
6. project schema file containing projects.enrolled_count
7. user_progress schema file
8. enrollment route code
9. API routes that expose enrolledCount
10. frontend surfaces that display enrolledCount

Audit:
1. Confirm every route that creates a user_progress/enrollment row.
2. Confirm whether enrollments can be created idempotently.
3. Confirm whether user_progress uniqueness prevents duplicate enrollments.
4. Confirm where projects.enrolled_count is exposed to clients.
5. Confirm whether enrolled_count is purely display/social-proof metadata now.
6. Identify the safest writer pattern.

Preferred implementation:
Durable writer + backfill.

A. Durable writer
When a new user_progress/enrollment row is created for a project, increment projects.enrolled_count atomically.

Requirements:
- Increment only when a new enrollment row is actually inserted.
- Do not increment on idempotent re-enroll/no-op.
- Preserve existing enrollment behavior.
- Avoid race bugs.
- Do not use enrolled_count for safety gates.
- Do not change /submit, /check, cert, billing, portfolio, or project content.

B. Backfill script
Add a one-shot idempotent script that recomputes projects.enrolled_count from user_progress.

Example:
scripts/src/backfill-enrolled-count.ts

Behavior:
- Read actual counts grouped by projectId from user_progress.
- Update projects.enrolled_count to match.
- Set zero for projects with no progress rows.
- Print before/after summary.
- Non-production safe by default.
- Require explicit allow flag if it could touch production.
- Do not delete rows.

C. Tests
Add tests that prove:
- first enrollment increments enrolled_count once.
- repeated/idempotent enrollment does not double-increment.
- different users enrolling same project increment correctly.
- backfill computes from user_progress correctly if practical with existing test harness.
- archive safety still uses user_progress helper, not enrolled_count.
