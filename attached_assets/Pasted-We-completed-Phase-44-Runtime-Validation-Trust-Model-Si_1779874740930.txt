PHASE 45 — Signed RunResult Envelope Library

Goal:
Implement the core signed RunResult envelope primitives in lib/execution-core only, with no product behavior change.

This phase should create the reusable, well-tested foundation for later runtime validation. It should not wire anything into /check, /submit, frontend, OpenAPI, or project content yet.

Implementation scope:

A. Types
Add types matching Phase 44 design:

* RunCapture
* RunEnvelope
* SignedRunEnvelope
* ValidationKind allow-list type if needed
* VerificationResult

RunCapture should include at minimum:

* userId
* projectId
* stepId
* code
* stdout
* stderr
* exitCode
* validationKind
* issuedAt
* expiresAt
* nonce

Envelope/hash material should include:

* submissionSha256
* outputSha256
* canonical payload string or canonical object
* signature
* key id / version if useful

B. Canonicalization
Implement deterministic canonical serialization:

* stable object key ordering
* explicit handling of arrays
* no hidden Date/string ambiguity
* no mutation of caller input
* consistent UTF-8 encoding expectations

C. Hashing
Implement SHA-256 helper:

* stable output
* hex or base64url format, but choose one and document it
* test deterministic behavior

D. Signing and verification
Implement HMAC-based signing unless Phase 44 design says otherwise:

* signRunEnvelope(payload, secret)
* verifyRunEnvelope(envelope, secret, options)
* constant-time signature comparison where practical
* expiry check
* project/step/user binding check if options provide expected bindings
* nonce hook or callback shape, but do not require DB integration yet

E. Tests
Add unit tests covering:

1. canonicalization is stable across object key order.
2. arrays preserve order.
3. signer/verifier round trip passes.
4. tampered stdout fails.
5. tampered code fails.
6. tampered projectId/stepId/userId fails.
7. expired envelope fails.
8. wrong secret fails.
9. malformed envelope fails safely.
10. caller input is not mutated.
11. signature comparison does not use plain equality if avoidable.
12. output hash and submission hash are deterministic.
